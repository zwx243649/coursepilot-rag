# 简历里的项目条目

导师让你「按给的简历格式写」，我这边没有拿到那份模板，所以下面准备了三种常见版式，直接挑一版贴进你的模板里，把技术栈和动词改成模板的写法就行。

---

## 版本一：标准版（三条要点，适合一页简历）

**课程资料 RAG 问答系统**（个人项目｜FastAPI · LangGraph · DashScope） 2026.09

- 独立设计并实现面向课程资料的 RAG 问答系统：支持 PDF / Markdown / TXT 上传与官方文档网址批量抓取，自动完成解析、切片（700 字 / 重叠 100）、向量化建索引；问答链路由 LangGraph 编排为「问题分析 → 向量检索 → 相关性判断 → 生成 / 拒绝」四节点状态图，回答强制标注原文引用，检索不到依据时直接拒答
- 从零搭建可复现的检索评测体系：自建 27 条标注用例（22 条可回答 + 5 条应拒答，覆盖两个课程语料共 236 个切片），实现 Recall@k、Precision@k、NDCG@k、MRR、判定准确率等指标，并封装为一键运行的评测脚本；据此把拒答阈值从 0.12 标定到 0.45，使 5 条无关问题全部正确拒答
- 用分层指标把失败拆成两类并分别归因：英文语料 Recall@5 仅 72.2%、放宽到 @10 回到 83.3%，据此区分「排序问题」（rerank 可解）与「语义匹配问题」（需查询改写），避免盲目调参；另定位到远程 embedding 偶发 20 秒以上抖动，规划超时重试与向量缓存

## 版本二：极简版（两条，适合压缩版面）

**课程资料 RAG 问答系统**（个人项目｜FastAPI · LangGraph · DashScope）

- 实现课程资料 RAG 问答系统：文档解析切片 + 向量检索 + LangGraph 四节点工作流（分析 / 检索 / 判断 / 生成或拒绝），回答带原文引用，无依据时拒答
- 自建 27 条标注测试集与评测脚本，量化 Recall@k / NDCG@k / MRR / 判定准确率；依据分数分布标定拒答阈值（0.12 → 0.45），无关问题误答率降至 0

## 版本三：偏工程能力（投后端 / 算法岗用）

**课程资料 RAG 问答系统**（个人项目）

- 架构：单进程 FastAPI 同时提供 API 与前端；SQLAlchemy 管理课程 / 文档 / 会话数据（SQLite，可切 PostgreSQL）；向量存储抽象为统一接口（当前本地实现，可切 Qdrant）；外部只依赖阿里百炼的 OpenAI 兼容接口（text-embedding-v3 向量化 + qwen-plus 生成）
- 工程细节：异步后台任务处理上传解析与网址抓取；文档状态机（queued / processing / ready / failed）与失败原因落库；配置集中由 `.env` 驱动并带哈希向量离线兜底；提供 `start.cmd` / `stop.cmd` 一键启停
- 质量保障：3 个后端接口测试 + 27 条评测用例的自动化回归脚本；用「标准答案切片」标注计算召回与排序指标，并内置标注校验（发现并修正了一处漏标导致指标虚低的问题）

## 这几句千万别写进简历

- ❌「支撑百万级数据」——实际 236 个切片，一追问就露
- ❌「使用 Qdrant / PostgreSQL 实现」——只写了配置、没实跑，被问「跑起来了吗」就崩；写「向量存储做成可切换接口，当前用本地实现，预留 Qdrant / PostgreSQL」既准确又显得懂设计
- ❌ 写没测过的指标（比如「准确率 95%」却没有测试集）——你现在的优势恰恰是**每个数字都能复现**
- ✅ 正确姿势：数字后面能接一句「怎么测的」，比如「Recall@5 = 96.2%，来自 27 条标注用例的自动化评测脚本」
