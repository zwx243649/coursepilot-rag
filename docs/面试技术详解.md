# 面试技术详解：五个必答题

本文按「切分 → 检索 → 评测体系 → 评测指标 → 发现问题与优化」五步组织，每一项都写清三件事：**是什么、为什么这么做、提升了多少**。所有数字来自项目实测（2026-09-28，27 条标注用例）。

---

## Q1　PDF 具体怎么切的？切分策略是什么？

### 是什么

三步：**页级抽取 → 去噪 → 窗口切分**。

```text
① pypdf 逐页读取，保留页码（切片不跨页，便于引用定位）
② 去噪：跨页重复行（出现率 ≥40% 且至少 3 页）判定为页眉/目录条丢弃；
        不足 12 字或不含字母汉字的噪声块（页码、装饰线、「谢 谢！」）丢弃
③ 窗口 700 字、重叠 100 字；边界按优先级选：
   标题 → 段落空行 → 句子结尾 → 空格 → 硬切
   重叠区不对齐字符，而是向后对齐到最近的句首
```

### 为什么这么做

- **为什么按优先级选边界**：旧实现只在标点里就近回退，结果出现过以 `lix (ref)`、`PI a ton` 开头的切片——从单词中间切断，语义直接损坏。
- **为什么去掉重复行**：课件每页印着相同的目录条，网页正文每页有导航文字，它们与问题无关却会进向量空间，稀释真正内容。
- **为什么不跨页**：引用要能落到具体页码；对「一页一知识点」的课件没有损失。

### 有什么效果（真实追踪）

| 文档 | 形态 | 切分结果 |
| --- | --- | --- |
| `03机器学习-逻辑回归.pdf` | 26 页 PPT，每页 20~300 字 | **一页一片，26 个切片**（平均 197 字）——700 的限制压根没触发 |
| `FastAPI ¶.md` | 单页 14,236 字网页正文 | **切成 26 片**（平均 625 字），24 片落在句子边界 |

优化前后：切片 243 → 236；含同一答案的重复切片 4 → 3；不再出现从断词开始的切片。

> 一句话结论：**切片粒度由材料形态决定**——课件是「一页一知识点」，网页正文才需要算法保证粒度。

## Q2　检索整体流程是怎么检索的？

### 是什么

```text
问题
 → ① analyze  去口语前缀
 → ② rewrite  中文问题 + 英文关键词（双语查询，失败回退原文）
 → ③ retrieve 向量化(1024 维) → 课程内召回 20 条 → 打分排序 → rerank 取 6 条
 → ④ grade    最高分 ≥ 0.45 → 生成；否则拒答（不调用生成模型）
 → ⑤ generate 按「文档名+页码+编号」拼上下文，qwen-plus 作答并标注 [1][2]
 → 返回：答案 + 引用列表 + 工作流轨迹
```

打分（本地向量库）：`0.8 × 余弦相似度 + 0.2 × 关键词覆盖率`。切换到 Qdrant 时是纯余弦，分数分布不同，**阈值必须重新标定**。

### 为什么这么做

| 环节 | 为什么需要它 | 不做会怎样 |
| --- | --- | --- |
| 查询改写 | 中文问题与英文资料用词不一致 | 英文语料 Recall@5 只有 72.2% |
| 候选 20 → 重排 6 | 正确切片常排在第 6~10 位，向量分数不足以精排 | 机器学习语料召回停在 92.3% |
| 拒答阈值 0.45 | 防止无依据作答 | 阈值 0.12 时 5 条无关问题全部被放行 |
| 缓存 + 重试 | 供应商接口会抖动 | 单次检索偶发 20 秒以上 |

### 提升了多少（同一套 27 条用例）

| 指标 | 优化前（仅向量召回） | 优化后（改写 + 重排） |
| --- | --- | --- |
| AI 语料 Recall@5 | 72.2% | **94.4%** |
| AI 语料 NDCG@5 | 0.826 | **0.911** |
| AI 语料 MRR | 0.806 | **0.917** |
| 机器学习语料 Recall@5 | 96.2% | **100%** |
| 判定准确率 | 无关问题全被放行 | **100%** |

## Q3　评测体系是怎么做的？

### 是什么

**27 条标注用例**（22 条可回答 + 5 条应拒答），覆盖 2 门课程、246 个切片。

每条可回答的用例标注「标准答案切片」；应拒答用例标注为不可回答。评测脚本先用接口核对标注是否存在、期望词是否真的落在标注切片里，再跑检索算指标。

### 为什么这么做

- **为什么要有标注而不是只看效果**：没有标注就只能"感觉回答还行"，无法说明系统稳定不稳定，也无法比较改动前后。
- **为什么要有应拒答用例**：拒答是系统的安全边界；不测就不知道阈值是否有效（我们第一轮就是被它抓出问题的）。
- **为什么要加校验**：「期望词必须真的出现在标注切片里」这条检查，把评测自身的错误挡在前面——我们确实踩过标注标窄导致指标虚低的坑。

### 有什么效果

评测体系让我能回答三个关键问题：**哪一项改动有用、改动值多少、改动值不值得保留**（BM25 就是被它否决的）。

## Q4　评测指标都有哪些？各自回答什么问题？

| 指标 | 定义 | 回答什么问题 |
| --- | --- | --- |
| **Recall@k** | 召回的相关切片数 / 标注切片总数 | 该找的资料有没有找全 |
| **Precision@k** | 召回的相关切片数 / 返回条数 | 返回的东西里有多少是相关的 |
| **NDCG@k** | 带位置折扣的排序质量 | 相关内容排得够不够靠前 |
| **MRR** | 平均 `1 / 首个相关切片排名` | 第一个正确答案出现得早不早 |
| **Hit Rate** | top_k 里至少命中一条的用例比例 | 最宽松的"有没有找到" |
| **关键词覆盖率** | 期望词在最佳命中切片中的占比 | 答案要素齐不齐 |
| **判定准确率** | （可答走生成 + 应拒答走拒答）/ 总用例数 | 系统的判断边界是否可靠 |
| **检索延迟** | 向量化 + 检索耗时（不含生成） | 检索侧性能，单独观测 |

### 为什么需要这么多

只有 Hit Rate 和 MRR 时，**分不清"召回不到"和"排序不好"**——而这两类问题的解法完全不同：召回问题要靠查询改写/切分，排序问题要靠 rerank。Recall 与 NDCG 的差值就是判断依据。

## Q5　评测发现了什么问题？怎么优化的？

### 问题一：拒答形同虚设（阈值拍脑袋）

- **现象**：5 条无关问题**全部**进入生成节点，虽然模型最后会说"资料里没有"，但工作流轨迹显示的是"生成"。
- **诊断**：把相关问题与无关问题的 Top1 分数打出来——相关最低 0.527，无关最高 0.413，中间有干净分界带，而阈值还是默认的 0.12。
- **优化**：阈值标定到 0.45，并保留哈希模式的低阈值兜底。
- **结果**：判定准确率 **100%**。

### 问题二：跨语言召回不到

- **现象**：中文提问去检索英文网页，Recall@5 只有 72.2%。
- **诊断**：查询与资料用词不一致——问「哪两个交互式文档界面」，切片里写的是 `Swagger UI / ReDoc`。
- **优化**：新增查询改写节点；并且**在代码里强制把原始问题与英文关键词拼在一起**（不能依赖模型自觉保留中文，实测它会整句翻译）。
- **结果**：AI 语料 Recall@5 **72.2% → 94.4%**。

### 问题三：排序不好，正确切片排在第 6~10 位

- **现象**：机器学习语料召回停在 92.3%，NDCG 只有 0.843。
- **诊断**：正确切片在候选集里，但向量分数排不进前五。
- **优化**：召回 20 条 → 交叉编码器 `BAAI/bge-reranker-v2-m3` 重排 → 取前 6。
- **结果**：机器学习语料 Recall@5 **96.2% → 100%**。

### 问题四：接口抖动造成 20 秒级长尾

- **现象**：正常检索 0.7 秒，偶发 20 秒以上。
- **优化**：超时从 120 秒降到 30 秒 + 3 次指数退避重试 + 向量落盘缓存。
- **结果**：缓存命中时单次检索 **110~150 毫秒**；断网也能用离线模式跑评测（8.2 秒跑完两个套件）。

### 问题五：切分带噪声

- **现象**：切片从单词中间开始；页眉、目录条、装饰页进了向量空间。
- **优化**：结构感知切分 + 跨页重复行过滤 + 噪声块过滤。
- **结果**：切片 243 → 236，重复切片 4 → 3。

### 被数据否决的优化：BM25 混合召回

- **做了什么**：实现 BM25 + RRF 融合，配置可开。
- **实测**：机器学习语料 Recall@5 **96.2% → 88.5%**（负收益），英文语料没有提升。
- **结论**：课件语料术语重复度高，关键词信号把近似切片推上来、挤掉正确答案 → **默认关闭**，但在文档里说明原因。

> 这一条比任何"我用了 X 技术"都更能说明工程判断：**能上也能下，依据是数据不是趋势。**

## 附一：重排融合策略的消融（方法论的体现）

换用硅基流动的 `bge-reranker-v2-m3` 后，我们发现"用哪个查询去重排"本身是个问题——中文资料用中文问题重排更好，英文资料用英文改写查询更好。于是做了四组对比：

| 融合策略 | AI Recall@5 | 机器学习 Recall@5 | 结论 |
| --- | --- | --- | --- |
| 仅用英文改写查询 | 94.4% | 92.3% | 中文资料吃亏 |
| 双查询取最大分 | 83.3% | 100% | 英文资料吃亏 |
| 按切片语言匹配查询 | 83.3% | 100% | 同左 |
| 两个排名 RRF 融合 | 77.8% | 100% | 英文资料最差 |
| **双语改写 + 单查询（采用）** | **94.4%** | **100%** | 两个语料同时最好，且只花一次重排调用 |

最终做法：改写时**强制拼接原始问题与英文关键词**，形成一条双语查询，检索与重排都用它——既保留中文语义，又补上英文术语。

## 附二：一次真实请求的完整追踪（可直接口述）

问题：**「梯度下降和最小二乘法有什么区别？」**

1. 清洗后仍是原句；
2. 改写为：`梯度下降法与最小二乘法的区别 梯度下降 least squares difference optimization iterative closed-form solution`；
3. 在课程内召回 20 条候选，第 1 名正是标准答案切片（检索分 0.775），第 2 名 0.617——**首尾之间有明显断层**；
4. 重排后取前 6 条交给模型；
5. 最高分远高于阈值 0.45 → 判定生成；
6. 输出答案并标注 `[1][2]` 引用，前端可展开原文片段，同时返回轨迹 `analyze → rewrite → retrieve → grade → generate`。
