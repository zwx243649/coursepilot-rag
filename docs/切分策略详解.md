# 切分策略详解（PDF 到底是怎么切的）

这份文档回答两个问题：**PDF 具体怎么切**、**切分策略是什么**。所有数字都来自项目里真实文档的追踪，不是举例。

配套代码：[`backend/app/services/parsing.py`](../backend/app/services/parsing.py)（`extract_pages` / `chunk_pages` / `_clean_text` / `_cut_point` / `_snap_forward`）。

---

## 一、三步流程

```
① 页级抽取      ② 去噪                ③ 切分
pypdf 按页读  →  跨页重复行过滤      →  窗口 700 字，按优先级选边界
保留页码         噪声块过滤             重叠 100 字，对齐到句首
```

### ① 页级抽取

用 `pypdf` 逐页读取，每页是一个独立单元并记录页码。**切片不跨页**——这是为了引用能精确落到「第 N 页」，代价是页与页之间不共享上下文。Markdown / TXT 没有页的概念，整体当作一页处理。

### ② 去噪（专治课件和网页正文）

两类噪声分开处理：

1. **跨页重复行**：统计每一行出现在多少页，出现率 ≥40% 且至少 3 页 → 判定为页眉/页脚/目录条，整行丢弃。
2. **噪声块**：去掉空白后不足 12 字、不含任何字母或汉字的块，或全由符号线条组成的块（页码、装饰线、「谢 谢！」这类收尾页）→ 丢弃。

标题单独成段时会被并入下一段，避免产生只有标题、没有内容的短切片。

### ③ 切分（700 字 / 重叠 100，可在 `.env` 调整）

在窗口内按下面的**优先级**依次找切口，命中即切：

| 优先级 | 边界 | 说明 |
| --- | --- | --- |
| 1 | Markdown 标题 | 保持章节完整，切在标题前 |
| 2 | 段落空行 | `\n\n` |
| 3 | 句子结尾 | `。！？；!?;` 与英文句点加空格 |
| 4 | 空格 / 换行 | 避免把英文单词切成两半 |
| 5 | 硬切 | 以上都没有时，才按字符切 |

约束：切口必须落在窗口长度 **50%** 之后，否则宁可再往前找，避免产出过短的碎片。

**重叠区不对齐字符，而对齐语义**：取上一片尾部约 100 字后，向后移动到最近的句首或行首，避免把半句话重复放进上下文。

## 二、真实追踪 A：PPT 课件（一页一片）

文档：`03机器学习-逻辑回归.pdf`（26 页，26 个切片）

| 步骤 | 结果 |
| --- | --- |
| 页级抽取 | 26 页 |
| 跨页重复行过滤 | 命中并丢弃 1 行：`3.逻辑回归求解`（它在多页反复出现） |
| 切片结果 | 26 个切片；长度最小 20 / 平均 197 / 最大 639 字 |
| 页面→切片 | 几乎每页恰好产出 1 个切片 |

**关键发现：这类课件根本没有被「切」。** PPT 每页文字量在 20~300 字之间，远低于 700 字上限，所以一页就是一个切片。此时真正起作用的是**页级隔离**和**去噪**，`700/100` 这两个参数基本没触发。

对检索的含义：切片粒度由材料形态决定。课件的天然粒度是「一页」（通常等于一个知识点），这对检索是好事——粒度干净、噪声少，所以机器学习语料的 Recall 明显高于网页正文。

## 三、真实追踪 B：网页正文（真正的窗口切分）

文档：`FastAPI ¶.md`（单页 14,236 字，26 个切片）

| 切片 | 范围 | 大小 | 切口类型 |
| --- | --- | --- | --- |
| #0 | 0-687 | 686 字 | 句子边界 |
| #1 | 595-1207 | 611 字 | 句子边界 |
| #2 | 1117-1659 | 541 字 | 句子边界 |
| … | … | … | 24 个切片都落在句子边界 |
| #9 | 4793-5489 | 695 字 | 空格边界（附近没有句末标点） |
| #25 | 14055-14236 | 181 字 | 文末收尾 |

**重叠区的对齐过程**（每次切分都会做）：

```
#0 结束于 687 → 硬算重叠起点 587 → 向后对齐到句首 595 → #1 从这里开始
#1 结束于 1207 → 硬算 1107 → 对齐到 1117
#2 结束于 1659 → 硬算 1559 → 对齐到 1561
```

也就是说：如果没有对齐，切片会从半句话中间开始，那半个句子会同时出现在两个切片里，既浪费上下文又干扰相似度计算。

**section 元数据**：这份文档只有一个一级标题（`# FastAPI ¶`），所以只有第一个切片带 section，其余为 `-`；多级标题的文档（例如课程讲义）会按最近的标题逐片继承。

## 四、两种材料的对比

| | PPT 课件 | 网页正文 |
| --- | --- | --- |
| 每页字数 | 20~300 字 | 14,236 字（单页） |
| 是否触发窗口切分 | 否（一页一片） | 是（切成 26 片） |
| 平均切片长度 | 197 字 | 625 字 |
| 主要收益来自 | 页级隔离 + 去噪 | 边界对齐 + 语义重叠 |
| 切片粒度 | 天然干净 | 需要算法保证 |

这也解释了评测里的现象：中文课件语料 Recall@5 达 100%，而英文网页语料只有 88.9%——**网页正文的切片本身就带着导航文字和重复段落，粒度再干净也比不上「一页一知识点」的课件**。

## 五、常见追问

**Q：为什么是 700 字、重叠 100？**
A：700 字大约容纳一个完整知识点，100 字重叠保证跨切片语义不被截断。换成论文或代码文档需要重新调这两个值，并用评测确认改动有效——不能凭感觉改。

**Q：为什么切片不跨页？**
A：为了引用能定位到具体页码。代价是跨页的语义被切断，对「一页一知识点」的课件没有影响，对连续叙述的长文档有影响（可以改成允许跨页，但要自己维护页码区间）。

**Q：为什么要丢掉重复行？**
A：课件的页眉、目录条、网页的导航文字会在每页出现，它们与问题无关却会进入向量空间，稀释真正内容。用「出现率 ≥40%」来判定，比手工维护黑名单更通用。

**Q：切片长度分布是什么样的？**
A：课件 20~639 字（一页一片），网页 181~697 字（窗口切分）。所有切片都不超过 700 字上限，这是切分器的不变量，有单元测试守着。

**Q：切分粒度会不会影响检索？**
A：会，而且是第一位的。切片是检索的最小单位：切太碎会丢上下文，切太大会引入无关信息。所以我们先用评测确认切分质量，再去调检索参数——顺序反了会白忙。
