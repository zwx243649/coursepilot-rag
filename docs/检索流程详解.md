# 检索整体流程详解

一次提问从进入系统到吐出答案，中间经过五个节点；其中**检索链路**（节点三）又包含向量化、召回、排序、重排四步。本文用真实追踪数据说明每一步在做什么、参数是多少、失败时怎么办。

配套代码：[`retrieval.py`](../backend/app/services/retrieval.py)、[`agent.py`](../backend/app/services/agent.py)、[`vector_store.py`](../backend/app/services/vector_store.py)、[`rerank.py`](../backend/app/services/rerank.py)。

---

## 一、总览

```text
用户问题
  │  POST /api/chat
  ▼
① analyze   问题清洗：去掉「请问 / 帮我 / 你能」这类口语前缀
  ▼
② rewrite   查询改写：LLM 把中文问题扩写成含英文术语的检索查询（temperature 0）
  ▼
③ retrieve  检索链路：
              ├─ 向量化    text-embedding-v3 → 1024 维（命中本地缓存则零调用）
              ├─ 候选召回  限定课程范围，取 20 条
              ├─ 打分排序  0.8 × 余弦相似度 + 0.2 × 关键词覆盖率
              │            （可选：BM25 稀疏检索 + RRF 融合，默认关闭）
              └─ 重排      gte-rerank-v2 对 20 条候选重排，取前 6 条
  ▼
④ grade     相关性判断：最好分数 ≥ 0.45 → 生成；否则 → 拒答（不调用生成模型）
  ▼
⑤ generate  上下文组装 + 生成：按「文档名 + 页码 + 编号」拼上下文，qwen-plus 作答
  ▼
返回：答案 + 引用列表（文档名 / 页码 / 片段 / 分数）+ 工作流轨迹（节点、决策、条数、耗时）
```

---

## 二、每一步做什么

| 节点 | 做什么 | 关键参数 | 失败时 |
| --- | --- | --- | --- |
| ① analyze | 问题清洗，得到检索查询词 | 正则去掉口语前缀 | 不会失败 |
| ② rewrite | 中文问题扩写成含英文术语的检索查询 | `QUERY_REWRITE_ENABLED=true`、temperature 0 | 回退原始问题 |
| ③ retrieve | 向量化 → 召回 → 打分 → 重排 | 候选 20 条、最终取 6 条 | 分层降级（见第五节） |
| ④ grade | 用检索分数决定生成还是拒答 | `MIN_RETRIEVAL_SCORE=0.45` | 无依据时拒答 |
| ⑤ generate | 组装编号上下文并生成引用型回答 | temperature 0.1、强制 `[1][2]` 引用 | 无依据不生成 |

## 三、一次真实请求的完整追踪

问题：**「梯度下降和最小二乘法有什么区别？」**（机器学习课程，2026-09-28 实测）

**① analyze**：原句无口语前缀，清洗后仍是原句。

**② rewrite** 输出的检索查询：

```text
梯度下降法与最小二乘法的区别 梯度下降 least squares difference optimization iterative closed-form solution
```

中文原句补上了 `least squares`、`closed-form solution` 这类英文术语——因为课件里这两种方法会以中英混排的形式出现。

**③ retrieve**：在课程范围内召回 20 条候选，前 6 名的检索分数分布：

| 排名 | 文档 | 切片 | 检索分数 |
| --- | --- | --- | --- |
| 1 | 02机器学习-回归.pdf | #17 | 0.775（**标准答案切片**） |
| 2 | 02机器学习-回归.pdf | #14 | 0.617 |
| 3 | 02机器学习-回归.pdf | #16 | 0.602 |
| 4 | 02机器学习-回归.pdf | #15 | 0.602 |
| 5 | 02机器学习-回归.pdf | #8 | 0.598 |
| 6 | 02机器学习-回归.pdf | #12 | 0.592 |

注意两点：**第 1 名与第 2 名之间有 0.158 的明显断层**（0.775 vs 0.617），说明这一问的语义匹配很干净；第 2~6 名挤在 0.59~0.62 之间，属于近似并列区，这种位置最容易被重排改变顺序。

**③' 重排**：本次调用**失败降级**——重排模型的免费额度已用尽（HTTP 403），系统自动保留检索顺序继续往下走，并在 `/api/system/health` 的 `rerank.last_error` 里留有记录，不会静默。

**④ grade**：最高分 0.775 ≥ 阈值 0.45 → 判定为「生成」，不走拒答分支。

**⑤ generate**：前 6 条按「文档名 + 页码 + 编号」拼成上下文交给 qwen-plus，提示词要求只依据上下文作答、用 `[1][2]` 标注引用。

**返回**：答案 + 6 条引用（可展开看原文片段）+ 轨迹 `analyze → rewrite → retrieve → grade → generate`。

## 四、打分的两个口径（换后端必须知道）

| 后端 | 公式 | 说明 |
| --- | --- | --- |
| 本地向量库（当前） | `0.8 × 余弦相似度 + 0.2 × 关键词覆盖率`，截断到 `[0,1]` | 关键词项让术语、专有名词类问题不被纯语义分数淹没；英文按单词、中文按单字 + 双字滑窗统计命中比例 |
| Qdrant | 纯余弦相似度 | 没有关键词项，分数整体比本地口径偏高，**切换后 0.45 这条阈值必须重新标定** |

阈值本身是量出来的：相关问题 Top1 分布在 0.527~0.747，无关问题在 0.224~0.413，取分界带中间的 0.45。哈希兜底模式自动降到 0.05。

## 五、四条降级路径（系统的鲁棒性设计）

| 情况 | 系统行为 | 影响 |
| --- | --- | --- |
| embedding 接口抖动 | 指数退避重试 + 结果落盘缓存 | 检索长尾从 20 秒级降到百毫秒级 |
| 查询改写失败 | 回退用原始问题检索 | 效果下降，流程不中断 |
| 重排失败 / 无额度 | 保留检索顺序（fail-open），健康检查暴露错误 | 机器学习语料 Recall@5 由 100% 回落到 92.3% |
| 断网或无任何额度 | 离线模式（跳过改写与重排，用缓存向量 + 本地检索） | 两个套件 8 秒跑完，零外部请求 |

设计原则是：**检索链路上每一环都可以单独失效，但整条链路不能断**。同时降级必须是可见的——日志 + 健康检查 + 评测模式都要能看出来当前跑的是哪条路径。

## 六、参数总表

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `EMBEDDING_MODEL` | `text-embedding-v3` | 向量化模型，1024 维 |
| `EMBEDDING_BATCH_SIZE` | 10 | 单次请求的条数上限（供应商限制） |
| `EMBEDDING_CACHE_ENABLED` | true | 向量落盘缓存，重复文本零调用 |
| `RETRIEVAL_CANDIDATES` | 20 | 进入重排的候选条数 |
| `RETRIEVAL_TOP_K` | 6 | 最终交给模型的切片数 |
| `MIN_RETRIEVAL_SCORE` | 0.45 | 拒答阈值 |
| `HYBRID_RETRIEVAL_ENABLED` | false | BM25 + RRF 混合召回开关 |
| `QUERY_REWRITE_ENABLED` | true | 查询改写开关 |
| `RERANK_ENABLED` | true | 重排开关 |
| `RERANK_MODEL` | `gte-rerank-v2` | 重排模型 |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | 700 / 100 | 切分参数（详见切分策略详解） |

## 七、这样设计的效果（消融实验）

| 配置 | AI 语料 Recall@5 | AI NDCG@5 | 机器学习 Recall@5 | 机器学习 NDCG@5 |
| --- | --- | --- | --- | --- |
| 仅向量召回（基线） | 72.2% | 0.826 | 96.2% | 0.887 |
| + BM25 混合召回 | 72.2% | 0.807 | 88.5% | 0.797 |
| **+ 查询改写 + 重排（当前）** | **88.9%** | **0.986** | **100%** | **0.896** |

结论：查询改写贡献最大（跨语言检索的关键），重排把排序质量推到接近满分；BM25 在这份以课件为主、术语重复度高的语料上是负收益，因此默认关闭——**技术栈不是越多越好，用评测说话**。

## 八、常见追问

**Q：为什么先改写再检索？**
A：改写的目的是让查询与资料写法对齐（术语、语言）。如果先检索再用原查询重排，跨语言问题仍然会漏掉正确切片——重排只能重排候选集里已有的内容。

**Q：为什么用 top1 分数判定拒答，而不是平均分？**
A：能不能回答取决于**是否存在一条足够相关的证据**，而不是平均下来像不像。平均分会被大量低分噪声稀释，导致明明有答案却拒答。

**Q：为什么只给模型 6 条切片？**
A：上下文不是越多越好。候选过多会稀释关键证据、增加成本；20 条候选经过重排取前 6 条，是召回率与信噪比之间的折中（`RETRIEVAL_TOP_K` 可调）。

**Q：检索延迟主要花在哪？**
A：几乎全在外部调用上——查询改写（LLM，约 1 秒）和查询向量化（约 0.7 秒）；本地向量检索在这个规模下只有几十毫秒。所以优化延迟的正确方向是缓存与并发，而不是改检索算法。

**Q：如果资料量涨到十万级切片？**
A：本地 JSON 实现是线性扫描，必须换成 Qdrant 这类带 ANN 索引的向量库；同时检索接口已经抽象成统一接口，切换不需要改业务代码，但**打分口径变化后必须重新标定拒答阈值**。

## 九、附录：优化前的检索流程（对照）

优化前的链路只有四个节点，没有查询改写、没有重排、没有缓存：

```text
问题 → analyze（去口语前缀）
     → retrieve（向量化 → 课程内 recall top_k=6 → 0.8×余弦 + 0.2×关键词 打分排序）
     → grade（最高分 ≥ 0.12 → 生成，否则拒答）
     → generate / refuse
```

需要说明的是，**打分公式（0.8 × 余弦 + 0.2 × 关键词覆盖率）和课程范围过滤从一开始就有**，不是后来才加的；变化的是它前后的环节。

当时的四个具体问题（全部由评测暴露）：

1. **跨语言检索吃亏**：中文问题直接去匹配英文网页切片，英文语料 Recall@5 只有 72.2%。
2. **排序没有二次校正**：召回顺序就是最终顺序，正确切片排在第六到第十位就救不回来（NDCG@5 0.826）。
3. **拒答形同虚设**：阈值沿用默认的 0.12，5 条无关问题全部进入生成节点——模型最后虽然会说「资料里没有」，但工作流轨迹显示的是「生成」而不是「拒答」。
4. **接口抖动没有防护**：单次请求、120 秒超时、无重试无缓存，偶发 20 秒级的检索长尾。

### 前后对照

| 环节 | 之前 | 现在 |
| --- | --- | --- |
| 工作流节点 | analyze → retrieve → grade → generate/refuse（4 个） | analyze → rewrite → retrieve → grade → generate/refuse（5 个） |
| 查询处理 | 只去掉口语前缀 | 额外做查询改写（补英文术语），失败回退原文 |
| 召回范围 | 直接取 top_k=6 | 先取 20 条候选，重排后取 6 条 |
| 排序 | 向量 + 关键词加权，一次成型 | 可选 BM25 + RRF 融合（默认关）＋ gte-rerank-v2 精排 |
| 拒答阈值 | 0.12（几乎不拦） | 0.45（按相关/无关问题分数分布标定） |
| embedding 调用 | 单次请求，120 秒超时，无重试无缓存 | 30 秒超时 + 3 次指数退避重试 + 落盘缓存 |
| 评测口径 | Hit Rate / MRR / 词覆盖 / 延迟 | 增加 Recall@k / Precision@k / NDCG@k / 判定准确率，并支持离线复现 |

### 效果差异（同一套 27 条标注用例）

| 指标 | 之前（仅向量召回） | 现在（改写 + 重排） |
| --- | --- | --- |
| AI 语料 Recall@5 | 72.2% | 88.9% |
| AI 语料 NDCG@5 | 0.826 | 0.986 |
| 机器学习语料 Recall@5 | 96.2% | 100% |
| 机器学习语料 NDCG@5 | 0.887 | 0.896 |

这张表也是「为什么要做这些优化」的唯一依据：**每一项改动都对应一个被量化的短板**，而不是因为某个技术看起来更先进。
