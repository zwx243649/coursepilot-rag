# CoursePilot 面试讲解稿

配套材料：[项目说明](项目说明.md)（模块、技术栈、评测体系的完整版）。这份稿子只解决一件事：**怎么把项目讲给面试官听，并且经得起追问**。

---

## 一、30 秒版（自我介绍里带一句）

> 我做过一个课程资料的 RAG 问答系统。场景是老师给的课件和官方文档太长，直接丢给大模型，它要么没见过这些资料、要么编内容。我的做法是把资料切片、用 embedding 建向量索引，提问时先做语义检索，再让大模型**只依据检索到的片段**作答，并强制标注引用；检索不到足够相关内容时直接拒答。技术上是 FastAPI 单体应用，问答流程用 LangGraph 组织成四节点状态图，向量化用阿里百炼的 text-embedding-v3，生成用 qwen-plus，另外配了一套固定测试集的检索评测。实测 9 条用例，top_k=5 时命中率 100%、MRR 0.787，端到端 5~7 秒。

## 二、2 分钟版（对方说「详细讲讲」时）

按这六段说，每段两三句，不要一口气全倒出来：

**1. 问题是什么。** 课程资料动辄几十上百页，直接问大模型有两个风险：模型没见过这些资料；模型会编造原文里没有的内容。我要解决的是「回答必须能追溯到原文」。

**2. 我做了什么。** 两个入口接资料：上传 PDF/Markdown/TXT，或者给一个官方文档网址批量抓取。资料进来后走同一条流水线：解析 → 切片（700 字、重叠 100）→ 向量化 → 建索引。问答侧是四个节点的状态图：问题分析、向量检索、相关性判断、生成或拒绝。返回给前端的除了答案还有引用列表和节点轨迹，用户能看见系统是怎么得出这个答案的。

**3. 关键选型。** 三件事我想说明理由：一是向量库我抽象成统一接口，演示阶段用本地 JSON 文件（零依赖），要上量就切 Qdrant，业务代码不用改；二是工作流用 LangGraph 而不是一堆 if/else，因为每个节点可以单独测试和替换，而且能把执行轨迹吐给前端；三是外部模型只依赖百炼的 OpenAI 兼容接口，所以换成 DeepSeek 或本地 Ollama 只改三行配置。

**4. 效果。** 我建了一套固定测试集：9 条问题，每条标注「期望在命中切片里出现的关键词」，指标是命中率、MRR、关键词覆盖率和检索延迟。实测 top_k=5 命中率 100%、MRR 0.787、平均检索延迟 652 毫秒；端到端一次问答 5~7 秒，其中检索只占 0.7 秒，其余是大模型生成。

**5. 最大的一个坑。** 我发现「拒答」没生效：拿 5 个无关问题去问，全部进了生成节点。虽然模型最后还是会说「资料里没有」，但工作流轨迹显示的不是拒绝，说明判断节点形同虚设。我把相关问题和无关问题的 Top1 分数都打出来，发现相关问题是 0.527~0.747，无关问题是 0.224~0.413，中间有一条干净的分界带，于是把阈值从 0.12 调到 0.45，改完再复验两类问题各走哪条分支。

**6. 现在的不足和下一步。** 三个短板我很清楚：没有 rerank，所以 MRR 只有 0.787，正确切片平均排在第 1~2 位、有几条掉到 3 位以后；没有查询改写，口语化提问的召回会掉；评测只覆盖检索，没有量化回答的忠实度。下一步优先接 rerank，再补 LLM-as-judge 做生成侧评分。

## 三、三个可以深讲的坑（面试官最爱听这个）

**坑 1：批量上限导致 400。**
26 个切片的文档索引失败，报 400。我把批次单独打接口、看原始错误体，发现百炼兼容接口对 `text-embedding-v3` 的单次批量上限是 10，而我配的是 16——小文档只有 2 个切片所以侥幸通过，大文档才暴露。改成 10 并把这条写进文档。
*体现的能力：会看原始错误、能定位到最小复现单元，而不是瞎试。*

**坑 2：拒答阈值形同虚设。**
见上文第 5 段。关键在于我没有停在「模型最后也会说没有」，而是去看工作流轨迹，发现判断节点没起作用，然后用分数分布去标定阈值，改完复验。
*体现的能力：有评测意识，改动用数据验证，不是凭感觉。*

**坑 3：换 embedding 模型必须重建索引。**
这件事最阴险的地方是**它不会报错**：如果你的向量库里一半是 A 模型、一半是 B 模型生成的向量，检索照样能跑，只是结果变得莫名其妙、分数整体偏低。所以我在代码和文档里都写死了这条规则：换模型或换维度，必须换 collection 名或重新索引。
*体现的能力：知道向量的语义依赖模型，理解「静默失败」比报错更危险。*

## 四、高频追问与回答

**Q：这个项目有多少是你自己写的？**
（一定会问，别绕）诚实回答：我用 AI 辅助写代码，但架构、选型、调参和排障是我做的。然后立刻用细节证明——比如主动讲切片为什么是 700/100、阈值 0.45 怎么来的、换模型为什么要重建索引。**能讲清楚细节，就是你的；讲不清楚，写多少行都没用。**

**Q：为什么不用 LangChain 的 RetrievalQA？**
它是黑盒，拿不到节点级轨迹，也不方便在检索和生成之间插自定义判断。我用 LangGraph 把流程显式建构成状态图，条件边让「拒绝」成为一等公民，前端还能把执行轨迹画出来。

**Q：怎么保证模型不胡说？**
三层：提示词约束（只依据给定上下文、资料不足就明说）、强制引用标注（每句结论对应 `[1]` `[2]`）、检索分数低于阈值时根本不调用生成模型直接拒答。第三层我用 5 个无关问题实测过。

**Q：你的指标怎么来的？样本多大？**
固定测试集，9 条问题，每条标注期望命中词，评测接口直接打检索侧，算命中率、MRR、词覆盖率和延迟。**样本很小，28 个切片，所以这些数字只能看趋势，不能当结论**——我会主动把这句话说出来。

**Q：数据量涨到百万级切片怎么办？**
现在本地 JSON 是逐条算余弦，线性扫描，几千条以上就该换。方案是切 Qdrant（HNSW 索引）、数据库切 PostgreSQL、索引构建从进程内后台任务换成真正的任务队列；因为向量库在代码里已经是抽象接口，切换不需要改业务逻辑。

**Q：为什么用 SQLite？不是说要用 PostgreSQL 吗？**
演示阶段 SQLite 零依赖、随项目携带，一条命令就能跑起来；生产形态在 compose 里配了 PostgreSQL，模型层用 SQLAlchemy 写的，切换只改连接串。**我没有实际跑过 PostgreSQL 那条路径，这点我不会说成已验证。**

**Q：5~7 秒的响应太慢了吧？**
延迟大头是生成（占 6.5 秒），检索只有 0.7 秒。三个优化方向：改流式输出改善体感、先把召回放宽再 rerank 降 token、对常见问题做答案缓存。

**Q：如果让你重做，你会改什么？**
我会把评测提到最前面做——先有固定测试集，再谈调参。我这次是先做完功能才发现拒答阈值没生效，如果一开始就有评测，这个坑会在第一天暴露。

## 六、这几句话千万别在面试里说

- ❌「支持百万级数据」——实际 28 个切片，说了必被追问，也圆不回来
- ❌「用了 Qdrant 和 PostgreSQL」——只写了配置没实跑，被问「跑起来了吗」就崩了；要说「预留了配置，实际用的是 SQLite + 本地向量文件」
- ✅ 正确说法：「这套向量库是抽象接口，演示用本地实现，切 Qdrant 只改配置」——同样的技术含量，但站得住
- ❌「命中率 100% 说明效果很好」——9 条用例，自己先把样本量说小，反而显得可信
- ❌ 不要把「AI 帮我写的」藏起来——诚实说用了 AI 辅助，然后用细节证明你理解

**最后一条心法：面试官不指望学生项目有百万用户，他看的是「你做决定时有没有依据、翻车后能不能查出来」。这个项目最值钱的不是你用了什么框架，而是那个「拒答没生效 → 量出分数边界 → 调阈值 → 复验」的完整过程。把这个故事讲好，比列十个技术名词都管用。**
